# GlobeTrotter Page Guidelines

Every application page should share the same structural language.

## Standard Structure
Navigation
↓
Page Header
↓
Primary Content
↓
Supporting Content
↓
Primary CTA/actions where appropriate

Adapt the structure to the feature; do not force identical layouts.

## Page Header
Generally use:
- Optional eyebrow/context
- Page title
- Optional description
- Optional primary action

## Dashboard
Prioritize welcome/context, upcoming/recent trips, quick actions, useful travel information, and secondary insights. Avoid overload.

## Trips
Prioritize trip discovery, creation, trip cards, status, dates, destination, and budget summary.

## Trip Details
Provide trip identity, destination, dates, budget, members, itinerary, and actions.

## Itinerary
Prioritize day, time, activity, location, duration, and cost. Keep the timeline scannable.

## Budget
Prioritize total budget, spent, remaining, category breakdown, expenses, and optimization.

## Discover
Prioritize search, filters, destinations, activities, useful metadata, and add-to-trip.

## Calendar
Prioritize dates, activities, travel events, and time conflicts.

## Profile
Prioritize identity, preferences, travel statistics, and account actions.

## AI Planner
Use the flow:
Input → Generation state → Preview → Edit → Save
AI output must still visually belong to the normal itinerary system.

## Collaboration
Prioritize members, roles, suggestions, votes, and comments. Make collaboration feel like part of the trip.

## Shared Trip
Expose only information intended for sharing and preserve GlobeTrotter visual language.

## CTA Rule
Each page should have a clear primary action. Avoid competing primary buttons.

## Information Density
Use cards, sections, tabs, progressive disclosure, and whitespace to keep travel information scannable.
